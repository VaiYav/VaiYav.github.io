Головна Компанія & вакансія Техстек LLM у продакшені Підготовка до інтерв'ю

Формат співбесіди (прогноз)

Зазвичай 2–3 етапи:

  1. HR / Recruiter call (15–30 хв). Мотивація, досвід, очікування по ЗП, англійська.
  2. Technical interview (60–90 хв). Розбір досвіду з LLM, питання по стеку, можливо live coding або system design.
  3. Final interview (CTO / Team Lead). Архітектура, AI-роадмап, культурна fit, запитання.

Self-pitch: структура

Бажаний обсяг — 2–3 хвилини. Формула:

  1. Хто я (10–15 с): «Я software engineer з X+ роками досвіду, останні Y років працюю з full-stack AI-рішеннями».
  2. Що я вмію (40–60 с): перелічи 2–3 найсильніші навички, що збігаються з вакансією: production LLM, React+Rails, eval/observability, RAG, cost optimization.
  3. Доказ (60–90 с): STAR-історія — конкретна фіча, що зробив, який був виклик, який результат.
  4. Чому Lexima (15–20 с): з'єднай їхній стек/продукт зі своїм досвідом.

Приклад self-pitch

«Я software engineer з 5-річним full-stack досвідом, останні 2 роки фокусуюсь на production LLM. Мій останній проєкт — внутрішній AI-асистент для автоматизації клієнтських запитів. Бекенд — Ruby on Rails + PostgreSQL, фронтенд — React + TanStack Query. Ми інтегрували OpenAI через Helicone, налаштували RAG з Qdrant, побудували eval на Ragas, і зменшили вартість запитів на 40% за рахунок caching + model routing. Я звик закривати задачі end-to-end: від UI до інфраструктури. Lexima цікавить, бо у вас вже працює AI в продакшені, і я хочу посилити цей напрямок».

Ймовірні питання та шаблони відповідей

1. «Розкажіть про ваш досвід з LLM у продакшені»

  • Вибери одну фічу.
  • Що робила, який стек, який був обсяг.
  • Які проблеми: cost, latency, quality, reliability.
  • Які рішення: model routing, caching, eval, fallback.
  • Результат: метрики (зниження cost, покращення accuracy, зменшення latency).

2. «Як ви оцінюєте якість LLM-виводу?»

«У мене три лінії оборони: (1) unit-тести на валідацію JSON-схеми, (2) reference-free метрики (faithfulness, answer relevancy) у моніторингу, (3) offline eval з golden set (answer correctness, factual correctness) у CI. Ragas/Promptfoo. Окремо збираємо human feedback і пускаємо LLM-as-judge на підмножину трафіку».

3. «Як ви оптимізували вартість/швидкість?»

«Спочатку вимірюємо: Helicone показує cost/latency по feature/model/user. Потім: (1) кеш частих запитів, (2) вибираємо дешевшу модель для простих задач, (3) скорочуємо промпти та зменшуємо max_tokens, (4) batching для async, (5) streaming для UX. Після кожної зміни — eval, щоб не втратити якість».

4. «Що робите при hallucinations?»

«Залежить від домену. Для factual задач: RAG + вимога ґрунтуватися на retrieved context + faithfulness guard. Якщо score низький — fallback. Для creative — самокритика/верифікація. Також system prompt hardening, output validation, prompt injection filters».

5. «Як ви проєктуєте REST API для AI-функції?»

«POST /api/ai/generate з job-об'єктом: повертаю {id, status} для довгих запитів. Клієнт polls GET /api/ai/jobs/:id або слухає SSE. Якщо real-time — SSE. Валідація вхідних даних, rate limits, idempotency key. Логування в Helicone».

6. «Розкажіть про ваш досвід з React Context і TanStack Query»

«Context — для інфрідентного глобального стану (auth, theme, feature flags). TanStack Query — для всього серверного: кеш, refetch, mutations, optimistic updates. Для AI-чату інколи використовую Zustand для локального message-стану, бо він змінюється кожен токен».

7. «Чому хочете працювати в Lexima?»

«Мене цікавить комбінація: вже працюючий AI-продукт, full-stack стек React/Rails/Koa, і фокус на внутрішню автоматизацію. Я хочу не просто писати код, а масштабувати AI-напрямок, вимірювати його impact і зменшувати вартість. Lexima — саме таке середовище: шукають інженера, який може закрити задачу end-to-end».

8. «Як ви вчитеся/тримаєте руку на пульсі?»

«Читаю release notes OpenAI/Anthropic/xAI, тестую нові моделі в prompt playground, аналізую експерименти, підписаний на технічні блоги (Helicone, Langfuse, OpenAI). Швидко збираю PoC і міряю на real data».

Чек-лист підготовки

Технічна підготовка

  • Повторити: React Context re-renders, TanStack Query lifecycle, Koa middleware order.
  • Rails: REST API, ActiveRecord N+1, transactions, background jobs.
  • PostgreSQL: EXPLAIN, індекси, JSONB, FTS, pgvector (для RAG).
  • Redis/RabbitMQ: кеш, черги, Pub/Sub, idempotency.
  • K8s/GitLab CI: deploy pipeline, migrations, secrets.
  • LLM: prompt patterns, eval metrics, RAG, Helicone.

Практичні навички

  • Приготувати 2–3 STAR-історії про LLM в продакшені.
  • Намалювати архітектуру RAG або streaming LLM на листочку/Excalidraw.
  • Вміти пояснити trade-off: cost vs latency vs quality.
  • Вміти обґрунтувати вибір інструмента (Helicone vs Langfuse vs LangSmith).
  • Повторити базові алгоритми/структури даних, якщо буде live coding.

Запитання, які варто поставити

Про продукт

  • Який саме бізнес-процес зараз автоматизує AI? Який happy path?
  • Скільки користувачів/запитів на добу? Який обсяг LLM-трафіку?
  • Який найбільший біль зараз: якість, cost, latency, масштабування чи тестування?
  • Чи є внутрішня база знань/документів, під яку плануєте RAG?
  • Який реальний вплив AI на бізнес? Як вимірюєте ROI?

Про команду та процеси

  • Як виглядає команда? Скільки фронтенд/бекенд/QA/DevOps/ML?
  • Хто буде моїм першим контактом? Як влаштований onboarding?
  • Який процес прийняття рішень: гіпотеза → PoC → eval → deploy?
  • Як часто релізите? GitLab CI + K8s вже налаштовані?
  • Як відбувається code review? Чи є лінтери, type check, pre-commit hooks?

Про AI/LLM

  • Які LLM-провайдери вже підключені? OpenAI, Grok, інші?
  • Чи є вже RAG? Якщо так — який vector store, embedding, chunking?
  • Як зараз eval'юація: онлайн, офлайн, golden set, human review?
  • Який бюджет на LLM? Як ми міряємо cost per feature?
  • Чи планується fine-tuning чи self-hosting моделей?
  • Як обробляєте prompt injection, PII, hallucinations?

Про роль та розвиток

  • Як виглядає перший місяць/90 днів? Які deliverables?
  • Які short-term та long-term цілі для AI-напрямку?
  • Чи буде можливість впливати на вибір технологій і архітектури?
  • Які можливості навчання, курси, конференції?
  • Очікування щодо англійської та міжнародної команди?

Red flags / green flags

Red flags

  • «У нас AI працює, але ніхто не знає як».
  • Немає eval, моніторингу cost, fallback.
  • Звучить як «підключи ChatGPT до всього».
  • Вимога працювати only-ai без підтримки backend/frontend.
  • Відсутність CI/CD, тестів, code review.

Green flags

  • Чітке розуміння: AI вже в продакшені, шукають посилення.
  • Є інструменти моніторингу (Helicone) і процес eval.
  • Команда цінує end-to-end ownership і експерименти.
  • Готові до фідбеку і дискусії trade-off.
  • Є зрозумілі short-term цілі для ролі.

Навігація по шпаргалці

Основна інформація зібрана в інших файлах:

  • Компанія & вакансія — факти про Lexima, продукт, команду.
  • Техстек — React, Rails, Koa, PostgreSQL, Redis, RabbitMQ, K8s, CI/CD.

Корисні фрази-запам'ятовувалки

  • «Я не просто викликаю API — я будую систему: prompt → eval → fallback → моніторинг → оптимізація».
  • «Метрики перш ніж оптимізація. Я не змінюю модель, поки не знаю, що саме ламається».
  • «AI — це feature, а не magic. Потрібні валідація, тести, rollback і чіткі контракти».
  • «Я обираю stack під задачу: Context для UI, TanStack Query для сервера, Zustand для швидкого message-стану».
  • «RAG — це 80% retrieval, 20% generation. Chunking та reranker важливіші, ніж модель».
